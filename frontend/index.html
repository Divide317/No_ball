COMPUTER VISION AND RULE ADJUDICATION SYSTEM

Automated No-Ball Detection for Broadcast and Practice Nets

CreaseGuard pairs two convolutional neural networks with a deterministic ICC and MCC rule engine. The system monitors a target directory containing crease/ and waist/ camera subfolders, evaluates incoming frames as they are written to disk, and checks fielding and bouncer restrictions for the active match format.

System Specifications
Crease Model (Law 21.5) Residual SE-CNN (99.71% val. accuracy, 1,697 frames)
Waist Model (Law 41.7) Residual SE-CNN (96.67% val. accuracy, 1,200 frames)
Spatial Explainability Stage-4 Grad-CAM activation overlay with peak reticle
Rule Engine Coverage T20I, IPL, ODI, Test, and 100-Ball playing conditions
Ingestion Pipeline Automatic directory polling (/crease and /waist)
Inference Runtime PyTorch 2.x and exported ONNX runtime checkpoints
01. Directory Ingestion

Subfolder Frame Watcher

Point the console at a parent folder containing crease/ and waist/ subdirectories. As camera frames are saved into either folder, the backend detects the file modification timestamp and triggers an evaluation automatically.

02. Dual Neural Networks

Front-Foot and Waist-Height Vision

Two separate Residual Squeeze-and-Excitation networks process the popping crease landing frame and the side-on batter frame in parallel. Each network outputs a calibrated probability and a Grad-CAM activation map.

03. Rule Verification

Format-Specific Playing Conditions

Alongside the visual models, the rule engine checks over bouncer quotas (Law 41.6), leg-side and behind-square-leg limits (Law 28.4), 30-yard circle restrictions (Clause 28.7), and Free Hit eligibility.

    DATASET SUMMARY

    Training and Validation Partitions

    The vision pipeline uses two separate convolutional classifiers trained on 2,897 labeled images (80% training, 20% validation). The crease dataset contains 1,697 broadcast and turf-augmented frames, and the waist dataset contains 1,200 side-on trajectory frames.

    Popping Crease Dataset: 1,697 Images Waist Trajectory Dataset: 1,200 Images Input Resolution: 128 x 128 RGB

    Network Configuration

    • Backbone: 4-stage Residual CNN (32, 64, 128, 256 channels)
    • Channel Attention: Squeeze-and-Excitation (reduction ratio 8)
    • Feature Aggregation: Concatenated Adaptive AvgPool and MaxPool (512-d)
    • Optimizer: AdamW with OneCycleLR and label smoothing (0.04)
    • Attribution: Stage-4 gradient-weighted class activation mapping
    INTEGRATION GUIDE

    REST API Endpoints & Deployment

    HTTP INTERFACE

    Backend Endpoints

    External camera scripts or scoring software can either write frames into the watched crease/ and waist/ subdirectories or submit images directly over HTTP.

    GET /api/folder/status - Poll watched folder and subfolder file queues
    POST /api/folder/select - Change the watched parent directory path
    POST /api/folder/evaluate - Run inference on active subfolder images
    POST /check-delivery - Direct multipart image and rule evaluation
    GET /api/metrics - Retrieve validation accuracy, F1, and confusion matrices
    Python Request Example 
    import requests

url = "http://127.0.0.1:8000/api/folder/evaluate"
payload = {
    "match_format": "T20",
    "over": 3,
    "ball_index_in_innings": 21,
    "bouncers_in_over_before": 0,
    "is_current_ball_bouncer": False,
    "fielders_leg_side": 3,
    "fielders_behind_square": 1,
    "fielders_outside_circle": 2,
}
res = requests.post(url, data=payload).json()
print(res["verdict"], res["ai_overstep_probability"], res["reasons"])
